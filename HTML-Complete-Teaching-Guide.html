What is HTML?

Hypertext Markup Language — the skeleton of every website

HTML is the standard markup language used to create and structure content on the web. It tells the browser what things are — a heading, a paragraph, an image, a link — while CSS handles how they look and JavaScript handles what they do.

🧠 In simple words

HTML is just a way of labelling your content so a browser understands it. You wrap your text in words like <h1> and <p>, and the browser instantly knows: "this is a big heading, that is a paragraph". Picture building a house: HTML is the bricks and rooms (the structure), CSS is the paint (how it looks), and JavaScript is the wiring that makes the switches work (what it does).

🆕 New words in this lesson
  • markup language — a way of decorating plain text with labels so a program understands it (HTML is not a programming language like Python).
  • tag — a keyword written inside < > brackets, such as <p>.
  • browser — the program that shows websites: Chrome, Edge, Firefox, Safari.
  • web page — one single screen of a website, saved as a .html file.
🧱 HTML

Structure — headings, text, images, links, forms. The content skeleton.

🎨 CSS

Presentation — colors, fonts, spacing, layout, animations.

⚙️ JavaScript

Behavior — interactivity, logic, dynamic updates.

Key facts every student must know

  • Full form: HyperText Markup Language.
  • It is a markup language, not a programming language — it has no variables, loops or conditions.
  • Files use the .html extension and open in a web browser (Chrome, Firefox, Edge…).
  • Tags are conventionally written in lowercase (<p> not <P>).
  • HTML files need no installation or compilation — just a text editor and a browser.
  • Current standard: HTML5, maintained by W3C / WHATWG as a "living standard".

The three layers of a web page

HTML Editors & Setup

Where to write your HTML code

HTML is written in any text editor. For learning, a modern code editor gives you syntax colours, auto-complete and error hints.

🧠 In simple words

You do not install HTML — it is already built into every browser. You only need two free tools: (1) a text editor to write the code — we recommend Visual Studio Code — and (2) a browser to view it. Your daily loop is just three steps: type → save → refresh.

Sublime Text Free/Paid desktop Very fast and lightweight

Online editors Browser-based CodePen, JSFiddle, W3Schools Tryit — no install needed

Workflow to run your first page

  1. Create a folder, e.g. my-website.
  2. Inside it, create a file named index.html (browsers treat this as the homepage).
  3. Write HTML code in your editor and save.
  4. Double-click the file — or drag it into a browser window — to view it.
  5. Keep the browser open; press Ctrl + S → Alt + Tab → refresh to see changes instantly.

Structure of an HTML Document

head vs body — settings vs content

Think of an HTML document as a person: the head is the brain (information about the page), the body is the face (what people see).

🧠 In simple words

Every HTML page has only two boxes.

Box 1 = <head> (the settings)
Holds the title, fonts, links to CSS. Nobody ever sees this on the page.

Box 2 = <body> (the content)
Every word, picture and button the visitor sees lives here.

One question settles everything: Can I see it on screen? Yes → body. No → head.

🆕 New words in this lesson
  • <!DOCTYPE html> — a note to the browser saying "this page uses modern HTML5". Always the very first line.
  • <head> — the settings zone. Nothing inside it is shown on the page.
  • <body> — the showing zone. Everything visitors see lives here.
  • <title> — the small text on the browser tab and in bookmarks.
  • metadata — hidden facts about the page (author, description, screen size) written with <meta>.

Tags, Elements & Attributes

The anatomy of HTML — the most important concept of all

Every piece of HTML is built from three parts. Understand these deeply and the rest of HTML becomes easy.

🧠 In simple words

Three words. One meaning each.

TAG = the keyword in <> brackets. Example: <p>

ELEMENT = the whole sandwich: opening tag + content + closing tag. Example: <p>Hello</p>

ATTRIBUTE = a setting written inside the opening tag. Example: <a href="page.html">

Memory trick: TAG = name · ELEMENT = full sandwich · ATTRIBUTE = knob that adjusts settings (never the content).

🆕 New words in this lesson
  • tag — the keyword in <> brackets, e.g. <p>.
  • element — opening tag + content + closing tag together, e.g. <p>Hi</p>.
  • attribute — an extra instruction inside the opening tag, written as name="value".
  • empty (void) tag — a tag with no content and no closing tag, like <img>, <br>, <hr>.
🏷️ Tag

The keyword in angle brackets: <p>. Usually comes in pairs (opening + closing).

📦 Element

Opening tag + content + closing tag: <p>Hello</p>. The box on the page.

🔑 Attribute

Extra info inside the opening tag: src="cat.jpg". Gives the element settings.

Rules of tags & attributes

  • Most elements are container (paired) tags: <p>…</p>, <h1>…</h1>.
  • Some are empty (self-closing) — no closing tag or content: <br>, <hr>, <img>, <meta>, <input>.
  • Attributes live only in the opening tag, written as name="value".
  • Attribute values should always be wrapped in double quotes.
  • An element can have many attributes but no two with the same name.

The text foundation of every page

HTML provides six heading levels, <h1> (most important) to <h6> (least), plus <p> for paragraphs of text.

🧠 In simple words

Headings are your page titles: h1 is the biggest and most important, h6 the smallest — like chapter titles in a textbook. A paragraph (<p>) is simply a block of normal text. HTML Text Formatting

Bold, italic, superscript, mark, and more

Modern HTML splits formatting tags into semantic tags (recommended — they carry meaning) and older physical tags (style only).

🧠 In simple words

These tags are different outfits for words: some make text bold or italic, some show a price was struck through, some lift text up like a power of 10 (superscript) or push it down like H2O (subscript). The one lesson that matters: prefer tags that carry meaning (strong, em) over tags that only change looks (b, i) — screen readers read that meaning aloud to blind users.

HTML Forms & Input Types

Collecting user data — the interactive heart of the web

Forms let users send data to a server: logins, sign-ups, surveys, searches. A form is a container (<form>) holding various input controls.

🧠 In simple words

Forms collect information — like a paper form, but digital.

How a form works, in 5 simple steps:
1. The <form> box holds every field and knows where to send them (action = the URL, method = how).
2. Every field has 2 halves: Label = the question ("Email:") and Input = the blank box. Connect them: for="mail" matches id="mail".
3. The visitor fills everything in.
4. The browser checks the fields for free — empty required field, email without @, age outside min/max, or text outside minlength/maxlength → it refuses to send.
5. Visitor clicks Submit → the browser packs every field as name=value pairs and sends them to the server → the server replies "Thank you!".

Two golden rules:
• An input without a name is never sent (the server would never know it existed).
• placeholder ≠ label — the placeholder disappears while typing, so it can never replace the question.

ℹ️
What actually gets sent?When the demo form above is submitted, the browser sends text like this: name=Asha+Sharma&email=asha%40example.com&course=html — every name attribute paired with what the visitor typed. That is why name is mandatory on every field.
🆕 New words in this lesson
  • form — the container that groups all the fields and knows where to send them.
  • input — one field the user fills in (text box, checkbox, date picker…).
  • label — the question or name of a field; must be linked to the input with for="id".
  • action — the URL that receives the data when the form is submitted.
  • method — GET (data shows in the URL) or POST (data hidden inside — use for passwords).

🏷️ name vs value — the pair that actually gets sent

🧠 In simple words

Think of a spreadsheet: every answer is filed in a row label and a cell.

name = the row label (the KEY) — the fixed heading the server looks for, e.g. name="email". It never changes, and if an input has no name, its data is never sent — the browser skips it completely.

value = the cell content (the ANSWER) — what is actually stored under that key. For a text box it is whatever the visitor typed; for radio, checkbox and hidden inputs it is the preset text you wrote (e.g. value="pro"); for a button it is the data sent when pressed.

Why both matter: radios all share ONE name (so the server knows they are one question) but each has a different value (so the server knows WHICH answer was chosen). Finally everything arrives as key=value pairs: email=asha@x.com&plan=pro.

Meaningful markup that machines understand

Semantic HTML means tags whose names describe their meaning, not just their look. It improves SEO, accessibility (screen readers) and maintainability.

🧠 In simple words

Semantic HTML means choosing tags by what they are, not how they look. Instead of a nameless box, you say <article> or <nav> — like labelling moving boxes "KITCHEN" instead of "STUFF". Search engines understand your page better, screen readers can navigate it for blind users, and your teammates thank you later.

Responsive Web Design Basics

One page that works on phones, tablets and desktops

Your same page must look good on a phone, a tablet and a laptop — you build it once, not three times.

🧠 In simple words

The problem: a phone screen is tiny. Open a normal website on a phone and the browser cheats — it zooms out so the whole page fits, and every letter becomes microscopic.

The fix is ONE line of HTML. The viewport tag tells the phone: "Don't zoom out. Show the page at real size — let the page itself shrink its parts."

Two more HTML tools help too:
• Fluid image — style="max-width:100%" means "never wider than my box". A big photo automatically shrinks to fit the phone.
• srcset — give the browser two sizes of the same picture; it picks the right one for the screen.

Everything else about responsive design (changing columns, fonts, colours on big screens) is done in CSS with media queries — that is a future course. In HTML, these three tools are all you need.

🆕 New words in this lesson
  • responsive — a page that automatically rearranges itself to fit any screen.
  • viewport — the visible area of the page on the user's device.
  • fluid — sized in percentages instead of fixed pixels, so it can stretch and shrink.
  • breakpoint — the screen width at which the layout changes (set in CSS with @media).
